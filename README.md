# File Toolkit

Windows 本地文件整理工具箱：按内容查重、按关键字归类、跨磁盘媒体索引。
纯 Python 标准库 + tkinter，PyInstaller 打包，目标机无需安装 Python。

## 功能

**查重清理** —— 按内容哈希找出完全相同的文件。大小预筛后只对候选文件计算哈希，支持
xxh3-128 / MD5 / SHA-1 / BLAKE2b / SHA-256 等算法。副本不删除，移动到待移除目录并留一份对照副本。

**查重(关键字)** —— 从文件名提取「字母 + 数字」关键字（可用自定义正则覆盖），把文件分到两个目录：
`移动到的目录`（关键字重复，以及内容重复组里保留的那一份，**需要人工复核**）和
`hash 重复文件`（内容完全相同的多余副本，**确认后可整目录直接删除**）。一步执行：扫描后弹确认框
列出数量与两个去向，确认即移动；不删除、不改名、不写任何报告文件。

**媒体索引** —— 扫描多个磁盘/目录的照片、视频、音频，只把文件名与元信息写入本机 SQLite。
拔盘后仍可按关键字跨盘查重、批量重命名、导出 CSV。

**照片重命名** —— 按 EXIF 拍摄日期 + 模板批量重命名照片/视频。日期基准可选
（拍摄日期 / 修改日期 / 创建日期），无 EXIF 时可回退到文件时间。两阶段：先只读分析，
写出 `plan.csv` 供逐条核对；执行按内存里的分析结果进行（**修改 plan.csv 不会影响执行**），
完成后写 `manifest_<时间戳>.csv` 台账。同名冲突自动加 `_001`，永不覆盖；执行前会校验文件大小，
分析后被改动过的条目直接跳过。支持中途停止、隐藏无需改名的行、把个别文件移出本次计划。

## 四页签设计意图

这一节记录四个页签**最初的设计目标**，作为后续改动的判断基准：功能该往哪扩、什么不该塞进来。

> **定位**：这是"辅助重复性工作"的本地小工具，不是全自动流水线。每个页签只负责一件事，
> 做到能完成它的那份工作即可，不追求功能齐全；需要判断、需要一次性处理的部分交回给人。

### 1. 查重清理

**意图**：一个人往往有多份备份（旧手机、移动硬盘、网盘下载），里面是同一批照片、音频等文件。
先指定一个目录为主目录，其余备份目录与主目录比对，**把重复的那份清理掉**，减少冗余。

**边界**：只处理文件内容，不改名；只负责"找出重复并移走"。
**不做的事**：不真删（重复项移入待移除目录，并留一份对照副本）；**不自动把额外目录里非重复的文件
并入主目录——那一步由用户手动完成**（工具只把重复的清掉，剩下的自然就是需要手动归并的部分）。

### 2. 查重(关键字)

**意图**：针对**单个目录**下的文件，按文件名关键字做简单查重；把"内容完全相同"与"关键字相同"
两类结果**分别提取**到两个目录，供人工决定。

**两个去向**：
- `hash 重复文件`：内容完全相同的**多余副本**。确认无误后可以**整个文件夹直接删除**，不用逐个看。
- `移动到的目录`：关键字重复的文件，以及每组内容重复里**保留的那一份**。这个目录是给人工复核/整理用的。

**边界**：只扫一层（不含子目录）；只认文件名里的"字母 + 数字"关键字（可用自定义正则覆盖）；
**不按媒体类型过滤**，目录里有什么就处理什么（音视频也一视同仁）。
**不做的事**：不自动删除（`hash 重复文件` 由用户确认后手动清空）；不做模糊相似度、不做内容语义分析。

### 3. 媒体索引

**意图**：把散落在不同磁盘/目录的照片、视频、音频，按关键字建立本机索引；能按关键字**跨盘查找**
同一关键字的媒体，即使原盘不在线也能查。

**边界**：只索引媒体文件；只把文件名与元信息写入本机 SQLite，不复制媒体本体。
**匹配兜底**：关键字规则匹配不到时（如 `IMG_2024.mp4`），**直接以原始文件名（去掉扩展名）作为关键字**，
保证文件仍然能被检索到，而不是从索引里"消失"。含 `@` 的文件名先按 `@` 后缀匹配，失败再用全名跑一次规则，
仍失败才用全名（`song@live1` → `LIVE1`，`abc123@xyz` → `ABC123`）。
**不做的事**：不做内容查重（那是查重清理的事）；不做云端同步。

### 4. 照片重命名

**意图**：安卓、iOS、相机导出的文件名规则各不相同（`IMG_1234`、`DSC0001`、长串哈希名……），
需要按统一规则重新整理，主要依据拍摄日期与命名模板。

**边界**：只重命名，不移动目录；同名冲突自动加序号、永不覆盖；先只读分析再执行。
**不做的事**：不做图像编辑；不猜内容；不保证所有格式都有元数据（缺失时回退文件时间）。

> 实现与上述意图如有出入，以 `CHANGELOG.md`（已修复项）和 `TODO.md`（遗留项）为准。

## 设计取舍与已知限制

下面这些都是**有意的取舍**，不是缺陷。后续审核或改动时请以此为准，不要再当作待修问题提出来：

- **不做全自动**：工具只替代重复劳动，需要判断的部分交回给人；不追求功能齐全。
- **查重清理不自动归并**：只把重复的那份清掉；额外目录里剩下的非重复文件由用户手动移动，工具不代劳。
- **查重(关键字)不按类型过滤**：单目录里有什么就处理什么，音视频也一视同仁。
- **媒体索引是快照，不保证实时**：索引记录的是扫描时刻的状态，文件被外部移动/删除后，右键该路径「更新关键字(重扫描)」即可同步；不做文件系统监听，也没有单独的「清理失效」入口。
- **媒体索引是派生数据，可重建**：索引和关键字都能通过重新扫描恢复；扫描不完整只影响“查得到/查不到”，不会动用户文件，因此不按数据丢失处理。
- **只索引本地文件**：OneDrive 等在线占位/云端未下载文件直接忽略，不触发下载；本地 junction/符号链接也按原策略跳过（避免绕圈），索引只覆盖本机可直接读取的内容。
- **重建关键字时界面可能短暂无响应**：这是小工具的取舍，不引入 WAL/分批；状态栏显示进度，可取消，取消时回滚、旧关键字保持不变。
- **扫描不完整时直接覆盖索引**：不为了“保留暂时读不到的记录”增加复杂判断，重扫即可恢复。
- **手工关键字不是长期数据**：右键「修改关键字」只是临时覆盖，重扫描会按文件名重新提取；丢失可接受。
- **「修改关键字」是全局替换**：右键改的是整个关键字（该词下所有文件一起改成新词或合并），不是单文件；这是设计行为。
- **媒体索引不做自由检索、不标注跨盘**：只提供“同一关键字涉及 ≥2 个文件”的查重视图和按路径查看，不提供关键字搜索框，也不标注同盘/跨盘。
- **规则匹配不到用原始文件名兜底**：媒体索引的关键字规则匹配不到时（如 `IMG_2024.mp4`），直接以原始文件名（去掉扩展名）作为关键字，保证“查得到”。
- **性能测试是 CPU 相对值**：用内存数据测纯 CPU 吞吐，不含磁盘 I/O，数字不代表真实查重速度。
- **照片重命名只管改名**：不移动目录、不做图像编辑、不猜内容；元数据缺失时按所选备选回退文件时间。
- **本地单机**：不联网、不上报、不需要管理员权限，也没有命令行入口。

## 安全边界

这个工具会移动和重命名你的文件，因此所有写操作都遵守以下原则：

- **没有静默操作**：执行前一律弹窗确认，列明数量与目标路径
- **移除 = 移动**：副本移入待移除目录，并在同级留一份 `[保留] 原名` 供人工比对，确认无误后再自行清空
- **两阶段执行（照片重命名）**：先只读分析产出 `plan.csv` 供核对，再执行；`plan.csv` 只读，
  改它不会影响执行
- **本地运行**：不联网、不上报、不需要管理员权限
- **重扫描不会误清离线设备**：重扫描前会检查根目录，拔掉的盘 / 离线网络盘会提示“不可访问”并跳过，不会清空其索引

> ⚠️ 请先在小范围目录试跑，确认结果符合预期后再用于重要数据。软件按 MIT 协议"现状"提供，作者不对数据丢失承担责任。

## 快速开始

从 [Releases](../../releases) 下载后解压，双击即可：

```
dist\
├── FileToolkit_onedir.exe      # 双击运行（需同目录的 _internal\）
├── FileToolkit_onefile.exe     # 单文件形态
└── _internal\                  # 依赖，勿删
```

无需安装 Python。首次运行会在 exe 同级生成 `media_index.db`（媒体索引库）。

## 命令行

**v20261029 起已移除命令行模式**（`--cli` / `--selftest`）。原因是这些入口要单独维护一套参数解析，
且绕过了 GUI 的安全检查：`--cli --apply` 不看目录包含关系、`--selftest --apply` 会直接移动文件。
现在 GUI 是唯一入口，所有写操作都走同一套确认与校验。

## 技术栈

- 语言：Python 3（标准库为主）
- 可选依赖：[xxhash](https://pypi.org/project/xxhash/)（未安装时自动回退 MD5，功能不受影响）
- 照片重命名依赖：[pillow-heif](https://pypi.org/project/pillow-heif/)（含 Pillow）、
  [piexif](https://pypi.org/project/piexif/)、[exifread](https://pypi.org/project/exifread/)；
  缺失时对应格式降级（HEIC 不可用等）
- 存储：SQLite（仅媒体索引页使用，`sqlite3` 内置）
- 界面：tkinter / ttk
- 打包：PyInstaller

## 项目结构

```
file_toolkit.py        # 入口：共用工具条、页签容器、任务互斥、配置读写
page_base.py           # 四个页签的共同基类（共享初始化、配置读写、运行锁默认实现）
common.py              # 业务内核：扫描、哈希、分组、关键字提取、执行、前置检查
util.py                # 通用工具：路径判断、长路径前缀、移动/复制、大小格式化
checker_page.py        # 查重清理页界面
dedup_page.py          # 查重(关键字)页界面
media_page.py          # 媒体索引页
media_db.py            # 媒体库 SQLite 层
media_scanner.py       # 媒体遍历与类型分类
media_query.py         # CSV 导出
photo_page.py          # 照片重命名页
settings_page.py        # 设置页（哈希算法 / 线程数量）
photo_rename.py        # 模板校验、命名生成、计划与执行
photo_media.py         # EXIF / HEIC / 视频元数据提取
config.py              # config.json 读写（四个页签的配置都存这里）
build.py               # 一键打包（读版本号、校验 CHANGELOG、保护 dist 里的运行数据）
run_tests.py           # 回归测试（不启动界面，40 项核心逻辑检查）
```
